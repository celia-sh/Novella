# Readium Swift Toolkit research

Date: 2026-08-25

## Version and integration

- The repository already pins Readium Swift Toolkit 3.11.0 in `apps/mobile/app.config.ts` through the `ReadiumShared`, `ReadiumStreamer`, and `ReadiumNavigator` CocoaPods from `https://github.com/readium/podspecs`.
- Readium Swift Toolkit 3.11.0 supports iOS 15.0 and therefore fits the app's current iOS deployment target of 16.4.
- The previous Novella Readium integration was removed by the Skia migration commit (`[COMMIT]`), but its iOS module, publication cache, preferences, locator mapping, and tests remain available in Git history as an implementation baseline. It must be adapted to current reader behavior, not blindly restored.

## Navigator APIs confirmed from Readium docs/source

- `EPUBNavigatorViewController` is a `UIViewController` implementing `VisualNavigator` and `Navigator`.
- It is created with `Publication`, `initialLocation`, optional `readingOrder`, and `Configuration`.
- `NavigatorDelegate.locationDidChange(_:)` exposes `Locator` updates.
- `Navigator.currentLocation`, `go(to:options:)`, `goForward(options:)`, and `goBackward(options:)` support restore and imperative navigation.
- `EPUBNavigatorViewController.firstVisibleElementLocator()` is available for the most precise visible-position capture before chapter/settings transitions.
- `VisualNavigatorDelegate.navigatorContentInset(_:)` allows stable custom top/bottom content insets; these values include the safe-area/chrome reservation and must be supplied from the existing `createReaderChromeInsets()` calculation.
- `EPUBNavigatorDelegate.shouldNavigateToNoteAt` and `shouldNavigateToLink` provide native-to-JS note/link events.
- `DirectionalNavigationAdapter` handles edge taps and keyboard navigation. It is not an outward boundary-swipe event, so the Novella wrapper must add a lightweight native boundary gesture/scroll-end event for chapter transitions rather than assuming the adapter covers the existing swipe contract.

## Preferences confirmed

- Readium uses `EPUBPreferences` and `submitPreferences(_:)`; applications submit preferences instead of mutating navigator settings directly.
- Reflowable EPUB preferences cover `fontSize`, `lineHeight`, `pageMargins`, `paragraphIndent`, `paragraphSpacing`, `publisherStyles`, `scroll`, `columnCount`, `backgroundColor`, `textColor`, and `theme`.
- `publisherStyles = false` is required for advanced typography preferences such as line height, paragraph indent, paragraph spacing, text alignment, and type scale to become effective.
- `scroll = false` enables synthetic pagination; `columnCount` controls one/two-column layout. The existing reader's paged mode can map to `scroll=false`, `columnCount=1`; double-page behavior can map to `columnCount=2` only where the existing large-screen policy allows it. If Readium's native spread behavior cannot match the current policy exactly, document the fallback and keep the user-visible mode functional.

## Progress model

- Readium explicitly does not define device-independent page numbers for reflowable content.
- `Locator.locations.progression` is the position within the current chapter/resource; `totalProgression` is the publication-wide percentage.
- This migration will use chapter `progression` for the novel chapter slider, because the existing slider is scoped to the current chapter and backend progress remains `chapterId + block locator`.
- `Publication.locate(progression:)` can create a locator for percentage-based jumps; the native wrapper should expose a `goToProgression` command or accept a locator generated by JS.
- JS will continue mapping the Readium locator to the canonical backend block locator using stable `nv-block-N` fragments, text anchors, and progression fallback.

## Publication/resource model

- `DirectoryContainer` can expose an on-disk directory and an explicit set of relative entries.
- `DefaultHTTPClient`, `AssetRetriever`, `DefaultPublicationParser`, `PublicationOpener`, and `EPUBNavigatorViewController` support opening a generated local EPUB directory.
- The publication can declare the complete chapter spine/TOC while materializing only the metadata, stylesheet, target chapter, and required WOFF2 font before first paint. Future chapter XHTML resources can be written into the same directory as existing chapter preload results arrive.
- The generated XHTML must keep stable chapter hrefs based on `chapterId`, deterministic `nv-block-N` fragments, current `processNovelFootnotes()` + `inlineNovelFootnotesAfterBlocks()` output, relative stylesheet/font references, and API-origin rebasing for relative images.
